# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An unofficial community documentation site for [Trail-code](https://github.com/trailhq/Trail-Code) (previously Graft; npm `@trailhq/trail-code`, CLI `trail`), built with Astro Starlight and organized by the [Diataxis](https://diataxis.fr/) framework. There is no application code here, only content, site config, and structural tests.

**Content rule: every page is the upstream README's exact text, reorganized.** Don't write new prose, summaries, or cross-links into pages. The only allowed edits are mechanical:

- section headings become page titles, and the remaining headings move up a level
- README anchors (`#benchmark`) are retargeted to site URLs (`/explanation/benchmarks/`)
- repo-relative links (`TELEMETRY.md`, `CREDITS.md`, `.env.example`, `LICENSE`) point to `https://github.com/trailhq/Trail-Code/blob/main/...`
- media markup is adapted for Starlight (see below)

The README's Contents list is dropped because the sidebar replaces it.

## Commands

```bash
npm run dev          # dev server at http://localhost:4321
npm run build        # static build to .vercel/output/static (Vercel adapter)
npm run preview      # serve the production build
npm run test:run     # all tests, once (npm test = watch mode)

npx vitest run tests/frontmatter.test.ts        # single test file
npx vitest run -t "every .mdx file should have"  # tests matching a name
```

`tests/build.test.ts` shells out to a full `npm run build`. Pass specific test files to skip it during quick iteration.

Prose lint: CI runs Vale on `src/content/docs`. `.vale.ini` points `StylesPath` at `styles/`, which isn't committed, so locally run `mkdir -p styles` before `vale src/content/docs` or Vale exits with an error.

Node >= 20.19 (CI uses 22).

## Syncing from upstream

When the upstream README changes, update all of these together:

1. Re-map the README sections onto the pages in `src/content/docs/`.
2. Update `src/data/source.json`: set `commit` and `commitDate` from `git log -1 --format='%H %cI'` in the clone, and set `generatedAt` to the current UTC time. The site-wide banner reads this file.
3. Regenerate `public/llms.txt`: keep its 8-line header (with the commit and time updated), followed by the raw README unchanged.
4. Copy any new or changed images from upstream `assets/` into `public/assets/`.
5. If the README's Mermaid diagram changed, update both `graph.mmd` and `public/assets/graft-architecture.svg`. The SVG is hand-written, not rendered from the `.mmd`.
6. Update `tests/pages.test.ts` when pages are added, renamed, or removed. Add a `redirects` entry in `astro.config.mjs` for any URL that goes away.

## How the site fits together

- **Content** lives in `src/content/docs/{tutorials,how-to,reference,explanation}/*.mdx`, loaded by Starlight's `docsLoader` (`src/content.config.ts`). `index.mdx` is the splash landing page. It holds the README's header block: the banner image and tagline go in the hero; the rest of the header, the note, the "how it works" diagram, "What changes in your agent", and License go in the body.
- **Sidebar** (`astro.config.mjs`): Tutorials are listed *explicitly by slug*, so a new tutorial must be added there. How-To, Reference, and Explanation are autogenerated and ordered by `sidebar.order` frontmatter, which follows README order.
- **Frontmatter**: every `.mdx` page needs `title` and `description` (enforced by `tests/frontmatter.test.ts`). Descriptions are sentences lifted from the section's own text.
- **Site-wide banner**: `src/components/Banner.astro` overrides Starlight's `Banner` slot. It always renders the "Unofficial community docs" notice with the source commit and sync time from `src/data/source.json`, then renders Starlight's default banner, so per-page `banner:` frontmatter still works.
- **Media adaptations**: GitHub's `<picture>` dark-mode sources become paired `<img class="light-only">` / `<img class="dark-only">`, which follow Starlight's theme toggle (the classes are defined in `src/styles/custom.css`). `<p align="center">` media blocks become `<div align="center">` so MDX doesn't nest paragraphs. `> [!NOTE]` becomes `:::note`. All images are served from `public/assets/` as `/assets/...`.
- **Landing hero**: `custom.css` stacks Starlight's `.hero` so the wide README banner (passed as `hero.image.html`) spans the full width. It also lays out the README badge row inline.
- **Component overrides**: `Footer.astro` wraps Starlight's footer (copyright line plus `@vercel/analytics`). `Head.astro` exists but is *not* registered in `astro.config.mjs`, so it is unused.
- **Astro whitespace**: HTML compression drops whitespace at line breaks next to tags. In `.astro` templates, use `{' '}` where inline elements meet text across lines.

## Deployment

The site builds to static output and deploys through the `@astrojs/vercel` adapter: pushes to `main` deploy on Vercel, and `npm run deploy` runs `vercel --prod` manually. The GitHub Actions workflow (`.github/workflows/deploy.yml`) runs only Vale and `npm run build` on pushes and PRs, not the Vitest suite.
