Each node in the Graft graph is a single Markdown file. Unlike code maps that only store addresses (file, line number), Graft nodes hold the **meaning** inline — so an agent learns what it needs without opening the source.

## What a node contains

| Part | Description |
|---|---|
| **Title** | The subsystem, API, or concept name |
| **Description** | Plain-English explanation of what this part of the system does and how it connects to the rest |
| **Typed links** | Wikilinks with relationship types: `depends_on`, `implements`, `produces`, etc. |
| **Content hash** | SHA hash of the source files this node represents, for stale detection |

## Link types

Nodes are connected via typed wikilinks:

```markdown
- depends_on: [[authentication-module]]
- implements: [[user-api]]
- produces: [[auth-token]]
```

These links create a navigable graph that agents can follow, just like following imports in source code.

## Why meaning, not just addresses

Most code maps stop at "this thing lives in that file, on that line." That tells an agent _where_ to look, not _what_ it will find. A Graft node holds the meaning inline, so the agent skips the file-opening step entirely.
