The graft map is vendor-neutral. Only the LLM-written parts, from `trail build --deep`, go through your provider key. Settings keep their `GRAFT_` names.

## Choose a provider

Set `GRAFT_PROVIDER` to one of:

| Value | Use it for |
|---|---|
| `openai` | Any OpenAI-compatible endpoint |
| `anthropic` | The native Anthropic API |
| `litellm` | A LiteLLM gateway that speaks the OpenAI-compatible format |
| `orcarouter` | An OrcaRouter gateway that speaks the OpenAI-compatible format |

Then set your key and model:

```bash
export GRAFT_PROVIDER=anthropic
export GRAFT_API_KEY=<your key>
export GRAFT_MODEL=<model>
```

## Point at an OpenAI-compatible endpoint

For the `openai` wire format, set `GRAFT_BASE_URL` to point at OpenRouter, Fireworks, Groq, a LiteLLM proxy, a local server, or OpenAI itself:

```bash
export GRAFT_PROVIDER=openai
export GRAFT_API_KEY=<your key>
export GRAFT_MODEL=<model>
export GRAFT_BASE_URL=<endpoint URL>
```

## Pass settings on the command line

```bash
trail build --deep --provider <provider> --model <model> --api-key <key> --base-url <url>
```

<Aside type="note">
`OPENROUTER_API_KEY` still works as a deprecated fallback, and `ORCAROUTER_API_KEY` as a second one. See the repo's [`.env.example`](https://github.com/trailhq/Trail-Code/blob/main/.env.example) for the full list.
</Aside>
