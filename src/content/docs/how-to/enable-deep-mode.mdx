By default, `trail build` uses tree-sitter: every symbol and call edge, no model, no key. `trail build --deep` adds plain-English summaries of each part of the system, written by the model provider you choose, under your own key.

## What deep mode adds

| | `trail build` | `trail build --deep` |
|---|---|---|
| Every function, class, and call edge (tree-sitter) | ✅ | ✅ |
| Per-file wiring cards | ✅ | ✅ |
| Concept nodes (file summaries + node synthesis) | | ✅ |
| Per-symbol one-line summary and crux excerpt | | ✅ |

## Run a deep build

<Steps>

1. **Set your provider**

   ```bash
   export GRAFT_PROVIDER=openai      # or anthropic, litellm, orcarouter
   export GRAFT_API_KEY=<your key>
   export GRAFT_MODEL=<model>
   ```

   See [Configure providers](/how-to/configure-providers/).

2. **Run the deep build**

   ```bash
   trail build --deep
   ```

   To summarize only some extensions:

   ```bash
   trail build --deep -e .ts .py
   ```

</Steps>

Every pass is cached by content hash, so re-running only touches the files that changed.

<Aside type="caution">
The `--deep` summaries go to the model provider you choose, under your own key. Plain `trail build` needs no key and never calls a model, and auto-sync never runs `--deep` for you.
</Aside>
